# ADR-005：审计与录像存储

- 日期：2026-10-12
- 状态：Accepted
- 上游：开发文档 v2「安全与权限·审计不可篡改」「执行网关·操作录像」

## 背景

所有写操作与 Agent 动作都必须可追溯；审计事件与录像只追加，删除与修改必须走单独审批流程，且审批过程本身也写入审计。主库选型见 ADR-001（PostgreSQL）。

## 决策

1. **审计存储**：与主库同一 PostgreSQL 实例，独立 schema 与独立数据库角色，角色**仅授予 INSERT**；用触发器禁止 UPDATE 和 DELETE。
2. **哈希链自建**：每条审计记录保存上一条记录的哈希，逻辑简单，不引入外部系统。
3. **哈希锚点**：定期把哈希链锚点写入外部对象存储并**开启对象锁（WORM）**（待实现，见修订记录）。仅库内哈希链不够——控制层被攻破时审计可被整体重算或尾部截断；锚点到位后才能兜底。锚点写入周期为运维配置项。
4. **节点录像**：放对象存储，同样开启对象锁；录像引用的输出与交互内容由网关统一采集。
5. 审计与录像的任何删除或修改需单独审批，且本身也写入审计。

## 后果

- 库内仅 INSERT + 触发器防护；库外 WORM 锚点（待实现）到位后整体重算不可行。
- 录像与锚点产生对象存储成本；冷存储策略须与保留期限一起确认。

## 待确认

- TODO(待决策)：保留期限——审计默认不小于 1 年；录像默认 90 天、超过 30 天转冷存储。以安全与合规最终确认为准（Q8，保持 TODO）。
- 对象存储平台：工程默认采用 **S3 兼容存储**，本地开发/测试用 MinIO（以 Object Lock 实现 WORM）；生产平台待运维确认（Q11，默认值待运维确认）。
- TODO(待决策)：审计 schema 命名、数据库角色命名、触发器与锚点写入周期，随审计模块实现批次落地。

## 备选方案

- 独立审计专用存储系统（如专用时序/只追加系统）：拒绝。增加运维复杂度，PostgreSQL 的 schema/角色/触发器组合已满足库内「禁止改删」要求（不含尾部截断，见修订记录）。

## 修订记录

- 2026-10-12（修订 1）：明确检测边界。**当前审计可检测中间篡改，不能检测尾部截断。尾部截断检测依赖外部锚点，待对象存储选型（Q11）确定后实现，列为 TODO。** 因此本系统不宣称「防篡改」，只宣称「可检测中间篡改 + 禁止改删（库内）」。
