# ADR-016：告警源画像匹配、无损迁移、人工重投与只读诊断执行

- 状态：已接受
- 日期：2026-10-12（第十七轮）
- 决策者：业务方裁决（本轮裁决 1–3）
- 关系：**不修改 ADR-001 至 ADR-015**。本 ADR 新增四项决策：
  ① 规划规则按"能力画像"匹配（修订 ADR-015 之后规划器的匹配口径）；
  ② 迁移脚本无损化（备份 + 可回滚）；
  ③ 死信人工重投（关闭 ADR-015 的"人工重新投递本轮不实现"TODO）；
  ④ 只读诊断执行器（第十六轮"本轮只规划不执行"的落地）

## 背景

第十六轮落地"规划器 + 计划表"后，评审指出四处问题：

1. **规则按原始 source 名称匹配太脆**：源名只要有一个字符不同（如 `prometheus` 与
   `prometheus-main`）规则即整体失效，且新增同类源必须改代码。
2. **迁移脚本有损**：`0002` 把 `test_alerts` 聚合重建为 fingerprint 主键时，
   **没有保留旧数据**，一旦回滚即永久丢失；且脚本中的注释自认 "lossy"。
3. **死信没有出口**：ADR-015 决定事件 5 次失败后置 `dead` 且不自动重试，
   但人工重投留作 TODO，运维无法恢复被误判的死信。
4. **执行器缺位**：规划器只写计划，没有任何组件执行只读诊断能力，
   链路止于计划表。

## 决策

### 1. 告警源"能力画像"与按画像匹配（P1）

- 每个白名单源**必须声明画像**：环境变量 `AGENT_OPS_ALERT_PROFILE_<SOURCE>`；
- 画像取值限定为四个已知值：`prometheus`、`alertmanager`、`docker-monitor`、
  `node-exporter`（`ingest.KnownProfiles`）；
- **启动校验（fail-closed）**：任一白名单源缺少画像环境变量 → 启动失败；
  画像值不在已知集合 → 启动失败。不存在"未知画像继续运行"的路径；
- 规划规则（`planner.Rule`）的匹配键由**原始 source 名称**改为**画像**
  （`Rule.Profile`），severity 仍精确匹配；
- **无匹配规则时计划状态为 `no_rule`**（不再是 `planned`）——
  `planned` 只表示"有匹配规则、待执行"，避免空计划被当成待执行计划；
- 源 → 画像的映射在启动时一次性解析，规划器只持有 `source → profile` 表，
  不接触规则表以外的东西。

### 2. 迁移无损化（P2）

`0002_alerts_fingerprint_pk` 重写为**先备份、再重建、可回滚**：

- **up**：
  1. 若备份表 `test_alerts_pre_0002` 已存在 → `RAISE EXCEPTION`，脚本失败
     （防止二次执行覆盖唯一一份备份）；
  2. 建备份表（结构 + 索引与旧表一致），把 `test_alerts` 全量复制进备份表，
     并对 `test_alerts_pre_0002_id_seq` 执行 `setval`；
  3. 建 `test_alerts_new`（fingerprint 主键），按 fingerprint 聚合
     （`SUM(count)`、`MIN(first_seen)`、`MAX(last_seen)`，source/summary 取
     `last_seen` 最新的那一行）；
  4. 删旧表、重命名新表；
- **down**：
  1. 备份表不存在 → 报错（没有可恢复的数据，拒绝静默成功）；
  2. 删聚合表；把备份表重命名回 `test_alerts`；
  3. 重命名序列与索引并修正 `OWNED BY`；
- 脚本中的 "lossy" 注释全部删除；
- 迁移测试**逐行逐列**比对：up 后备份行数 == 旧表行数；down 后恢复出的每一行
  与原始数据在所有列上完全相等，且备份表已被删除。

### 3. 死信人工重投（P3，仅测试模式）

新增命令 `alerts redrive`：

```
alerts redrive -mode test -event-id <N> -confirm -operator <name>
```

- **必须**同时满足：`-mode test`、`-confirm` 已给出、`-operator` 非空、
  事件存在、事件状态为 `dead`；任一不满足即**拒绝**且**不做任何修改**
  （各自的错误常量见 `internal/redrive`）；
- 通过后：`status → pending`、`attempts → 0`、`next_attempt_at/consumed_at` 置空，
  并写入 `test_redrive_log`（event_id、operator、previous_status、created_at）；
- 全程在**一个事务**内完成，`SELECT ... FOR UPDATE` 锁行；
- 只允许操作 `test_` 前缀的表（表名守卫）；
- 本轮**仅测试模式**：非 test 模式一律拒绝（生产重投留待后续轮次 + 审批）。

### 4. 只读诊断执行器（P4，新增 `alerts/internal/executor`）

- 输入：`status=planned` 的计划；通过 **CAS**
  （`UPDATE ... SET status='running' WHERE id=$1 AND status='planned'` +
  `RowsAffected()==1`）抢占，保证同一计划**只执行一次**；
- 对计划中的**每一条能力**，按固定顺序判定：
  1. 未在只读能力注册表中声明 → `denied`（fail-closed，不执行）；
  2. 非 `read_only` / `destructive` / `test_only` → `denied`（不执行）；
  3. 能力名以 `k8s.` 开头（Kubernetes 画像）→ `deferred`，
     **不发起任何集群请求**（Run 调用计数必须为 0）；
  4. **必须调用 `policy.Evaluate`**，结果必须是 `auto` 且 tier 为 `read_only`，
     否则 `denied`（不执行）——**不允许绕过策略直接调用适配器**；
  5. 通过后执行：本轮只执行 **linux**（linux 适配器）与 **docker-monitor**
     （docker 适配器）两类画像；
- 结果写入 `test_diagnosis_results`，`UNIQUE (plan_id, capability)` +
  `ON CONFLICT DO NOTHING`（重复执行不产生重复结果）；
- **凭据屏蔽**：写入结果表与审计 payload 前，对 `key=value` 形态的凭据类字段
  统一屏蔽；
- **审计**：每次尝试写一条事件（`diagnosis.executed` / `diagnosis.denied`），
  actor 固定 `diagnosis-executor`，target 为 `plan-<id>`，seq 连续；
- **计划终态**：全部成功 → `done`；任一失败 → `failed`；
  全部 `deferred` → `deferred`；其余（含 `denied`）→ `partial`；
- **隔离性**：单个计划失败（含执行器内部错误）**不影响其他计划**；
- 执行器**不做**任何写操作、不读 Kubernetes Secret、不连接生产资产。

## 影响

- `alerts/internal/ingest/ingest.go`：新增 `EnvProfilePrefix`、`KnownProfiles`、
  `ProfileName`、`KnownProfile`；`SourceSet` 新增 `profiles`；
  `NewSourceSet` 缺少/未知画像即报错；新增 `ProfileFor`/`Profiles`/`Names`；
- `alerts/internal/planner/rules.go`：`Rule.Source` → `Rule.Profile`；
  新增状态常量 `StatusNoRule`/`StatusRunning`/`StatusDone`/`StatusFailed`/
  `StatusDeferred`/`StatusPartial` 与原因 `ReasonNoProfile`/`ReasonDeferredK8s`；
  `PlanFor(profile, severity)`；
- `alerts/internal/planner/store.go`：计划表新增 `profile` 列，
  status CHECK 扩展为 7 态；`Config.Profiles`；无匹配时写 `no_rule`；
- `deploy/migrations/0002_alerts_fingerprint_pk.{up,down}.sql`：无损化；
- `alerts/internal/redrive/`（新增）：人工重投；
- `alerts/cmd/alerts/main.go`：新增 `redrive` 子命令；
- `alerts/internal/executor/`（新增）：只读诊断执行器 + 凭据屏蔽；
- `alerts/internal/chain/`：新增端到端用例（含执行器与结果表）；
- ADR-015 的其余决策（处理顺序、桶表有界、重试退避与死信）继续有效；
  ADR-015 §3 的"人工重新投递本轮不实现"TODO 由本 ADR §3 关闭。
