# ADR-001：主数据库选型（PostgreSQL）

- 日期：2026-10-12
- 状态：Accepted
- 备注：该决策在 ADR-002~006 起草前已确认，本文件为落地于仓库的补记，供 ADR-003/ADR-005 引用。
- 上游：开发文档 v2「部署与高可用」（高可用的关系型数据库）

## 背景

控制层需要承载资产清单、变更与审批、告警、诊断会话状态等业务数据，并须支持：

1. 事件与业务变更在同一事务内写入（outbox，ADR-003）；
2. 网关写操作的分布式锁/租约选主（同一资产的写操作串行化）；
3. 主从复制与自动切换的高可用形态；
4. 审计与业务表的存储隔离（ADR-005）。

## 决策

主数据库使用 **PostgreSQL**，为唯一主库：

1. 支持表分区：审计与事件表按时间分区管理；
2. 主从复制 + 自动切换，高可用方案成熟；
3. 事务特性直接支撑 outbox 模式与租约选主，无需额外组件；
4. 审计与主库同实例、独立 schema 与独立数据库角色（仅 INSERT），见 ADR-005。

## 后果

- 单一数据库技术栈，运维负担最小；控制层无状态、状态集中的部署模式依赖该库可用性。
- 依赖不可用时系统进入只读模式（可查询与诊断、暂停写操作），与开发文档要求一致。
- 数据库版本与分区所需特性需在部署基线中固定；outbox 与审计表的膨胀需监控与保留策略（Q8/Q17）。

## 备选方案

- MySQL：生态同样成熟，但本系统对事务性 outbox、分区与 JSON 处理的需求下，PostgreSQL 更贴合；且与既有决策一致。
- 独立审计专用存储：拒绝，见 ADR-005「备选方案」。
