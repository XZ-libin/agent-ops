# ADR-003：事件与 outbox

- 日期：2026-10-12
- 状态：Accepted
- 上游：开发文档 v2「接口设计·事件」「核心模块」

## 背景

模块之间只通过内部接口与事件交互，事件包括 `asset.changed`、`health.degraded`、`diagnosis.completed`、`change.approved`、`execution.finished`。需要一种可靠、低运维成本的发布方式。

## 决策

1. 第一阶段**不引入消息队列**，使用 **PostgreSQL outbox**：业务变更与事件在同一数据库事务内写入 outbox，消费者轮询投递（内部接口为事件投递的消费端）。
2. 事件体公共字段与开发文档保持一致：`id`、`type`、`subject`、`ts`、`trace_id`，保证一次完整处置过程可串联。
3. **诊断辅助服务作为 outbox 消费者**（Q3 已决策）：诊断请求事件写入 outbox，诊断服务轮询消费并回写结论；控制层不直接调用诊断服务。
4. 将来确需消息队列时迁移到 **NATS JetStream**，届时单独评估 outbox → JetStream 的迁移方案，不在本期引入。

## 后果

- 事务内写入保证事件不丢；复用已有 PostgreSQL，无新增中间件运维负担。
- 轮询存在投递延迟，吞吐受数据库限制；事件量显著增长后按本 ADR 的迁移路径切换。
- 主库已承担 outbox 与租约选主（见 ADR-001），需监控表膨胀。
