# ADR-006：凭据管理与风险分级

- 日期：2026-10-12
- 状态：Accepted
- 上游：开发文档 v2「风险策略与审批」「安全与权限·凭据管理」

## 背景

所有写操作必须经过风险策略判定，任何一步都不能跳过；凭据集中托管，网关执行时临时获取。

## 决策

### 凭据

1. 密钥服务用 **Vault**；SSH 直连启用 **SSH CA 签发短期证书**，不使用长期密钥——与 Teleport 思路一致。
2. 若公司已有云厂商 KMS，优先复用，不再另部署一套（现状待确认，Q12）。
3. 网关执行时临时获取凭据，**不落盘、不写入日志**。
4. 每个适配器使用独立服务账号，权限仅包含其能力清单所需的最小集合。

### 风险分级

5. 等级（Tier）四档：`read_only` / `low` / `medium` / `high`；决策（Decision）三档：`auto` / `require_approval` / `deny`（见 proto/agent_ops/contract/v1/risk.proto）。
6. 上下文因素（环境、影响范围、可逆性、冻结窗口）**只升级等级，不直接改决策**；等级→决策的映射写在策略配置里。
7. 禁止操作双重防线：第一道是**不声明该能力**；第二道是策略中的**硬拒绝规则**，能力即使被误声明也不会执行。
8. 策略引擎独立判定，不采信 Agent 对自身风险的描述；低可信度诊断结论不触发自动执行。

## 后果

- 短期证书使 SSH 直连无长期密钥可泄露；风险模型可解释、可审计。
- 需维护策略配置与分级用例测试：每次修改策略都要求全部用例通过，并对比变更前后判定差异（开发文档要求）。
