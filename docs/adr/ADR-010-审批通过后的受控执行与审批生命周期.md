# ADR-010：审批通过后的受控执行与审批生命周期

- 状态：已接受（第十轮修订：先占后执行、重评语义、pending 去重粒度；
  第十一轮修订：执行租约与对账、错误码决定）
- 日期：2026-10-12（第九轮；第十轮 2026-10-12 修订；第十一轮 2026-10-12 修订）
- 决策者：业务方已确认审批窗口与四眼原则；其余为工程默认

## 背景

第八轮 require_approval 只创建 pending 记录；第九轮实现批准后的受控执行，
并引入仅测试目录的写能力验证写路径。以下决策超出 ADR-001~007 范围，
按约束新立本 ADR。

## 决策

### 1. 审批生命周期（状态机扩展）

状态：pending → approved / rejected / expired；approved → executing / expired；
executing → consumed / abandoned。rejected / expired / consumed / abandoned
为终态（第十轮新增 executing 与 abandoned 两条迁移边）。

第十一轮起 executing 记录携带**执行租约** `lease_until`（见 §8）：租约即
"该执行仍在进行"的凭据，对账与单实例守卫都以它为依据。

- executing：**先占后执行**的抢占态。执行方必须以一条原子 CAS
  （`UPDATE ... WHERE id=$1 AND status='approved'`，检查影响行数）把审批从
  approved 置为 executing；抢占失败者不执行、不写执行审计（见 §4）。同一审批
  不可能被两个执行方执行。
- abandoned：抢占成功但未产生终态（进程崩溃，或幂等跳过）时的放弃态，由对账
  标记（§6）；**不重放**——同一个审批不能再自动执行，需重新提交审批。
- 批准后的执行不自动触发（不做自动执行调度），由调用方显式调用网关的
  ExecuteApproved；consumed 表示"该审批已被一次执行消费"，消费后不可再次执行。

### 2. 审批窗口（业务方已确认，工程默认 30 分钟，可调整）

- 待审批请求 30 分钟未处理（pending.expires_at 到期）即过期；
- 已批准请求 30 分钟内必须执行（自 approved_at 起算），否则作废（置 expired）；
  抢占（Claim）与消费（Consume）都在库层校验该窗口，超窗即作废；
- 两个窗口的判定统一使用注入时钟（approvals.WithClock），批量为
  ExpirePending / ExpireApproved，执行路径由 Claim / Consume 惰性作废。

### 3. 四眼原则（业务方已确认，无例外）

审批人必须与请求人不同（approver != record.actor），测试环境同样强制；
不满足即拒绝批准并保持 pending。运营上需要至少两个具备审批权限的账号
（可先用两个测试账号模拟，待团队人员安排确认）。

### 4. 批准后的执行路径（第十轮修订：先占后执行 + 重评语义修正）

ExecuteApproved 固定顺序（第十轮起生效；第九轮"执行后再置 consumed"的写法
被判定存在 consumed 窗口缺陷，已被本次修订取代）：

1. 校验审批：存在、状态 approved、请求内容哈希与请求人一致、**审批人存在且
   不同于请求人（四眼）**；
2. 能力查找（未声明即拒）→ destructive 拒绝 → test_only 不得出现在生产注册表；
3. **策略重评（第十轮修正语义）**：只拦截"不可通过审批解除"的条件——
   能力不存在、destructive=true、test_only 出现在生产注册表、策略返回 deny。
   `require_approval` 本身由已存在的有效审批满足（未过期、未消费、审批人不同
   于请求人），**不再被拦截**。第九轮"重评必须返回 auto"是阻塞缺陷：
   所有 require_approval 的请求（中/高风险能力、生产环境能力）即使已批准也
   无法执行。网关低风险白名单同理——审批在创建时已满足该门控；
4. **原子抢占（先占后执行）**：单条 `UPDATE ... WHERE status='approved'`
   的 CAS 把审批置为 executing；影响行数为 0 时返回"审批已被使用或已过期"，
   不执行、不写执行审计；
5. 写 gateway.executing 审计（先于幂等与执行；失败即 fail-closed，审批停留在
   executing，由对账标记 abandoned，不重放）；
6. 幂等检查（同键只执行一次；422/409 语义同第八轮）；
7. 执行注册表 Handler → 写 executed / failed 审计；
8. 审批置 consumed（executing → consumed）：执行终态审计已写入，此时才闭合
   审批生命周期。

幂等跳过（422/409）时，已抢占的审批被标记 abandoned：抢占已消耗该审批的一次
使用权，且幂等键不可复用，唯一语义是"需重新提交审批"（绝不重放）。

destructive=true 的能力即使已批准也在网关直接拒绝，绝不触达执行层（SSH）。

### 5. 生产能力目录与仅测试能力

- 契约新增字段 Capability.test_only（bool，第九轮 contract diff）：
  标记"仅测试目录声明"的能力；
- 网关注册表默认拒绝 test_only=true 的声明；仅 NewTestRegistry（测试配置）
  可加载——加载生产配置时该能力不可见（补测试：TestProductionCatalogInvisibleToTestOnly、
  TestRegisterProdRejectsTestOnly）；
- 生产能力目录（linux manifest）不包含任何写能力；生产低风险自动执行清单为空
  （gateway.DefaultConfig）；
- 测试写能力 test.write.marker / test.write.marker.delete 声明于测试目录
  gateway/internal/testwrite（manifest.yaml，test_only: true）：
  在 /tmp/agent-ops-test/ 下写入/删除固定前缀（agent-ops-marker-）的标记文件，
  路径经 internal/validation 校验（不接受任意路径），命令一律 argv
  （mkdir -p / touch / rm），互为回滚（PlanRollback）。

### 6. 执行前审计与对账（R4；第十轮扩展到审批层）

执行前先写 gateway.executing（含唯一 execution_id）；执行结束写
gateway.executed / gateway.execution.failed；幂等重放/跳过以
gateway.execution.replayed / gateway.execution.skipped 闭合。
进程在 executing 后崩溃时记录保持 executing，由 gateway.Reconcile 对账：

1. 审计层：扫描无终态事件的 executing，追加 gateway.execution.abandoned 标记；
2. 审批层：状态为 executing 且未产生终态审计的审批，标记 abandoned
   并写 approval.abandoned 事件——覆盖"CAS 抢占成功、executing 审计尚未写入
   即崩溃"的窗口。

abandoned 的写操作绝不自动重放：重试命中审批状态（executing/abandoned → 
FAILED_PRECONDITION）与幂等存储的 abandoned/409 语义（同 key 永不复用）。
对账应在进程启动、对外提供服务之前执行（工程默认，待运维确认）。

### 7. pending 去重粒度（第十轮修订）

pending 去重键由 (actor, idempot_key) 修正为 **(actor, request_hash)**：
同一请求内容即使换了幂等键，也只保留一条 pending 记录并返回已有审批 ID。
(actor, idem_key) 的"仅 pending"唯一约束保留，仅用于**原子地**判定
"同一幂等键、不同内容"的冲突（422）：两条部分唯一索引 + `INSERT ...
ON CONFLICT DO NOTHING` 使并发下的去重与冲突判定都不依赖应用层先查后写。
审批记录的请求哈希**不含幂等键**（参与幂等哈希的内容与参与审批哈希的内容
按用途分离，ADR-009 规则不变）。

### 8. 执行租约与对账口径（第十一轮修订）

裁决：**单实例前提下**用租约消除"启动对账把在飞行执行误判为中断"的风险。

- 抢占（Claim）时写入 `lease_until = now + lease`（默认 60 秒，工程默认，
  业务方可调）；执行期间每 20 秒续期一次（`approvals.Renew`，必须明显短于租约）；
- 续期失败（含租约过期）→ 取消执行上下文 → Handler 中止 → 写
  `gateway.execution.failed` 审计 → 审批标记 `abandoned`：
  **不重放、不消费**（远端结果未知，唯一语义是"需重新提交审批"）；
- **对账只处理租约已过期的 executing 记录**（`lease_until <= now`，含无租约记录）；
  未过期的一律跳过——它可能仍在执行中；
- 启动时若检测到其他实例的有效租约，拒绝启动（单实例约束）；
- **多实例部署在该机制完善前被明令禁止**；改造方向：跨实例租约协调
  （数据库行锁 / lease 表 CAS 租借）与对账口径调整。
- 对账仍只在启动后、对外服务前执行（§6 前置条件不变）。

### 9. 执行失败与"不存在"的错误码决定（第十一轮）

固定映射（ADR-008 第十轮修订同款）之外，本轮明确两个边界情形：

- **执行失败（`failed` 结局）→ `INTERNAL`**：错误码只表示"服务端未完成该操作"，
  具体原因（含执行租约中止）通过 `ExecuteOutcome` 详情回传，不额外占用错误码
  语义空间；
- **记录不存在 → `NOT_FOUND`**：保持 gRPC 标准语义，不并入
  `FAILED_PRECONDITION`（那条留给"状态不允许"）。

## 影响

- approvals 表结构：状态 CHECK 增加 executing / abandoned；新增
  (actor, request_hash) WHERE status='pending' 唯一索引（去重）；
  (actor, idem_key) WHERE status='pending' 唯一索引改名保留（冲突判定）；
- 状态迁移表扩展：approved → executing → consumed / abandoned；
- 新增审计事件类型：approval.abandoned；
- 契约 Gateway 服务新增 RPC（ADR-008 第十轮修订 §5）：SubmitExecute /
  Approve / Reject / ExecuteApproved / GetApproval；actor 取自 gRPC metadata
  （仅测试静态 token 认证，不得用于生产）。
