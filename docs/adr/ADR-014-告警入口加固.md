# ADR-014：告警入口的加固（去重语义、源边界、限流、部署形态与消费者骨架）

- 状态：已接受
- 日期：2026-10-13（第十五轮）
- 决策者：业务方裁决（本轮裁决 1–5）
- 关系：**不修改 ADR-013 的已定决策**；本 ADR 记录对 ADR-013 相关实现的修订与新增边界

## 背景

第十四轮落地告警入口（ADR-013）后，评审指出四处需要收紧/补齐：

1. AST 守卫的"入站 HTTP"范围未显式登记——任何文件都能起监听端口；
2. 去重语义为"窗口外新增一行"，持续告警会让行数随时间线性增长；
3. 告警源没有白名单、没有每源密钥、没有限流——拿到密钥即可无限写入；
4. 没有部署形态，也没有 outbox 的下游消费者。

## 决策

### 1. AST 守卫：入站允许文件显式登记（修订 ADR-013 §7 的细分）

| 类别 | 允许文件 | 说明 |
| --- | --- | --- |
| 出站 HTTP | `adapters/docker/client.go`、`adapters/kubernetes/client.go` | 不变（ADR-011/012） |
| 入站 HTTP | **仅** `alerts/internal/httpapi/server.go` | 本轮新增登记 |

- 入站符号（`http.Server`、`http.ServeMux`、`http.NewServeMux`、`http.HandleFunc`、
  `http.Handle`、`http.ListenAndServe`）出现在**未登记文件**即失败（fail-closed）；
- 入站允许文件同样不得出现任何出站符号；
- 监听与优雅停机因此集中在 `httpapi`（`Server.Run`），`cmd/alerts` 不接触 `net/http`。

### 2. 去重语义改为 fingerprint 主键 upsert（修订 ADR-013 §3）

`test_alerts` 以 **fingerprint 为主键**，每个 fingerprint 至多一行：

- 窗口（5 分钟，以窗口起点 `window_start` 起算，注入时钟）**内**重复：
  只更新 `count` 与 `last_seen`，**不新增行、不写 outbox**；
- 窗口**首次打开/重开**（`window_start <= now - 5min`）：`count` 重置为 1、
  `window_start = now`，并写入一条 outbox 事件 `alert.received`；
- 行数上限由**不同 fingerprint 的数量**决定，不再随持续时间增长；
- 原子性：单条 `INSERT ... ON CONFLICT (fingerprint) DO UPDATE`（行级锁），
  "本次是否打开窗口"由 SQL 以 `window_start = now AND count = 1` 判定——
  并发同刻请求不会重复写 outbox。

### 3. 告警源边界：白名单 + 每源密钥 + 每源限流（新增，ADR-013 未覆盖）

| 项 | 决策 |
| --- | --- |
| 源白名单 | `AGENT_OPS_ALERT_SOURCES`（逗号分隔）；缺失或为空 → **拒绝启动** |
| 每源密钥 | `AGENT_OPS_ALERT_KEY_<SOURCE>`（SOURCE 大写、连字符转下划线）；任一已列出源缺密钥 → **拒绝启动** |
| 白名单外源 | **403**，且**不做签名校验、不写任何表** |
| 跨源密钥 | 用其他源的密钥签名 → **401** |
| 速率限制 | 每源令牌桶 **60 次/分钟、突发 10**；超出 → **429 + Retry-After** |
| 限流时机 | **先于签名校验**（未鉴权源同样受限，避免用随机 source 绕过）；按 source 名分桶 |
| 时钟 | 去重窗口与限流均通过注入时钟控制 |

请求处理顺序：读体（64KB 上限）→ 解析 → **限流** → **源白名单** → **签名（该源密钥）**
→ 字段校验 → 去重 upsert → outbox。

### 4. 部署形态（新增）

- 新增 `alerts/cmd/alerts`：配置全部来自环境变量与显式参数；`-mode` 必填，
  `mode=prod` 本轮**直接拒绝**（生产认证未实现）；启动前校验源白名单、每源密钥、
  DSN 库名必须是 `agent_ops_test`（复用 `internal/testdb`）；
  监听地址默认 `127.0.0.1:8088`，支持优雅停机；
- `deploy/docker-compose.alerts.yaml`：**测试专用**叠加文件（`profiles: ["test"]`），
  依赖测试数据库服务，仅绑定 `127.0.0.1`；密钥为明显的测试假值
  （`test-only-key-*`）并在文件中注明；生产密钥由运维注入，**绝不写入仓库**。

### 5. outbox 消费者骨架（新增，仅骨架）

- `alerts/internal/consumer`：读取 outbox 中 `alert.received` 且 `status='pending'`
  的事件，按事件 ID 升序处理；
- 幂等：写入 `test_diagnosis_requests`，`event_id` 唯一约束 + `ON CONFLICT DO NOTHING`，
  重复消费不产生新行；处理完成后把事件标记 `consumed`；
- 写记录与标记 consumed 在**两个独立事务**中完成：两者之间崩溃时事件保持 pending，
  重启后跳过重复写入并补标记，不产生重复记录；
- **本轮不做诊断**：不调用任何适配器、不执行任何命令；待诊断记录状态固定 `pending`。
- 诊断规则引擎留待第十六轮。

## 影响

- `internal/repoguard` 新增 `AllowedInboundHTTPFiles` 与入站符号判定；
- `alerts/internal/ingest` 新增源白名单/每源密钥（`SourceSet`）与令牌桶（`Limiter`）；
- `alerts/internal/store` 的 `test_alerts` 改为 fingerprint 主键（含 `window_start`），
  `test_outbox` 新增 `status`/`consumed_at`；
- 新增 `alerts/cmd/alerts`、`alerts/internal/consumer`、`deploy/docker-compose.alerts.yaml`、
  `deploy/Dockerfile.alerts`；
- ADR-013 的其余决策（HMAC 方案、64KB、severity 白名单、表名守卫、每轮 schema、
  不做诊断）继续有效。
