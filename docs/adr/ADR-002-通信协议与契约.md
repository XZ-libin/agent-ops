# ADR-002：通信协议与契约

- 日期：2026-10-12
- 状态：Accepted（2026-10-12 修订：契约唯一源收敛为 protobuf，见决策 3）
- 上游：开发文档 v2「接口设计」「执行网关与节点 Agent」「可观测性」

## 背景

系统分控制层、执行网关、诊断辅助服务、节点 Agent 与前端五种进程。契约若以某一语言的代码为源，其余语言会漂移或沦为二等公民。

## 决策

1. 控制层 ↔ 执行网关：gRPC。本批次先落地两个占位接口（Health、QueryAssets）；写操作、指令与回执通道随后以**双向流**定义。
2. 对外：REST，HTTP/JSON，路径前缀 `/api/v1`。错误格式统一 `code` / `message` / `request_id`，并区分可重试与不可重试。
3. 契约唯一源：**protobuf（proto/）**。**OpenAPI 由 proto 生成**，不手写、不重复定义（api/ 目录只存放生成产物）。生成代码：Go 用 buf + protoc-gen-go；TypeScript 用 openapi-typescript、Python 用 datamodel-code-generator（Pydantic），二者消费由 proto 生成的 OpenAPI。**禁止手写镜像类型。**
4. CI 必须包含 `make gen-check`：重新生成代码并与仓库内生成产物比对，不一致即失败，防止手改生成文件。由 proto 生成的 OpenAPI 与 TS/Python 产物在生成管道接入后一并纳入 gen-check。
5. 写操作必须携带 `Idempotency-Key`：PostgreSQL 表 `idempotency_keys`，作用域按「操作人 + 接口 + key」隔离；同键同内容返回已存响应，同键不同内容返回 422，同键处理中返回 409；有效期 24 小时（工程默认值，待运维确认）。

## 后果

- 单一源（proto）防漂移，三端类型一致；生成产物须进版本库（保证 CI 可校验）。
- 需要维护代码生成工具链（版本已固定在 Makefile 与 CI）。
- proto → OpenAPI 的生成管道尚未接入（需给 gateway.proto 补 HTTP 注解并接入 openapi 插件，见后续批次待办）；接入前 REST 契约以 proto 中的服务定义为准。

## 工程默认值（待运维确认）

- 节点 Agent 心跳周期 30s、连续 3 次未心跳判离线、指令签名 Ed25519（Q4）；双向流消息形状随执行通道批次定义。
- 幂等键有效期 24 小时（Q10）。

## 备选方案

- 以 Go struct 为源：拒绝。Go 专属，Python 与前端成为二等公民。
- OpenAPI 与 protobuf 双源并存、维护映射：拒绝（Q2 已决策 proto 单源，删除重复定义）。
- 三端各自手写镜像类型：拒绝。三个月内必然漂移。
