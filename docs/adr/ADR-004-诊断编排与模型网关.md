# ADR-004：诊断编排与模型网关

- 日期：2026-10-12
- 状态：Accepted
- 上游：开发文档 v2「Agent 编排与诊断会话」

## 背景

诊断会话是「创建（待处理）→ 收集（只读能力）→ 分析（假设）→ 验证（再次收集证据）→ 结论或升级」的显式过程，含步数上限、总耗时上限、单资产并发上限、人工介入点与只读工具白名单等约束。这些全部是业务规则，且必须可追溯、可审计。

## 决策

1. 诊断编排：**自研显式状态机**（Python，diagnostics/）。状态与约束按开发文档直接编码，便于审计。不使用 LangGraph；仅当未来多智能体循环变得复杂时再评估引入。
2. LLM 调用：前面加**统一模型网关**，先用托管 API；若合规要求数据不能出网，改为自部署开源模型（如 vLLM 托管）。模型网关工程默认采用**自研薄封装**（脱敏 → 托管 API → 用量与延迟记录），不引入现成网关（Q14，默认值待运维确认）。
3. 安全约束：日志、告警正文、工单内容一律视为不可信数据，调用 LLM 前**必须脱敏**；Agent 只能调用资产所属适配器声明的只读能力；诊断会话内不直接执行写操作，只能产出变更方案。
4. 模型选择：先以一批历史故障样本做评测，比较各模型结论准确率后再定，不凭印象选用。

## 后果

- 状态机显式、可审计、依赖少；副作用是后续多智能体协作仍需在自研状态机上自行演进。
- 模型网关多一层封装，换来模型可切换、脱敏与用量统一治理的单一入口。

## 待确认

- 单次会话 ≤ 50 步、总耗时 ≤ 30 分钟、单资产并发诊断 ≤ 2（工程默认值，待运维确认，Q15）。
