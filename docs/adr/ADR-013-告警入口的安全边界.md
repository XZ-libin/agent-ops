# ADR-013：告警入口的安全边界

- 状态：已接受
- 日期：2026-10-13（第十四轮）
- 决策者：工程默认（待运维确认项已标注）

## 背景

第十四轮新增 `alerts` 组件（告警入口，Go 模块 `github.com/ORG/agent-ops/alerts`）：
接收外部告警源推送的告警（`POST /v1/alerts`）、校验签名、去重、写入告警表与
outbox 表，为后续诊断规则引擎（第十五轮）提供数据。

告警入口是**第一个对外的写入端点**：它暴露在网络上、接受外部输入、并直接写库。
因此需要一份代码层面的边界决策，超出 ADR-001~012 的范围，按约束新立本 ADR。

## 决策

### 1. 认证：HMAC-SHA256 签名（fail-closed）

| 项 | 决策 |
| --- | --- |
| 算法 | HMAC-SHA256，hex 编码 |
| 签名内容 | `timestamp + "." + 原始请求体`（时间戳参与签名） |
| 请求头 | `X-AgentOps-Timestamp`（Unix 秒）、`X-AgentOps-Signature` |
| 密钥来源 | 环境变量 `AGENT_OPS_ALERT_HMAC_SECRET`，**代码中不硬编码任何真实密钥** |
| 容忍窗口 | 时间戳与服务器时间相差超过 5 分钟即拒绝（工程默认，待运维确认） |
| 失败响应 | 签名缺失 / 不匹配 / 时间戳非法或超窗 → **401**（不区分具体原因，避免探测） |

未配置密钥时服务**拒绝启动**（`httpapi.New` 直接返回错误）。

### 2. 输入校验

| 项 | 决策 |
| --- | --- |
| 请求体上限 | **64KB**，超出 → **413** |
| `severity` | 只接受 `info` / `warning` / `critical`，**严格匹配**（不做空白/大小写修正）→ 否则 **400** |
| `fingerprint` | 必填（空或全空白 → 400） |
| `source` / `asset_id` | 必填（工程默认，待运维确认） |
| `received_at` | **由服务端注入**（忽略请求体中的同名字段），保证时间可信 |
| 其他方法 | 仅 POST，其余 → 405 |

### 3. 去重窗口

同一 `fingerprint` 在 **5 分钟**内只写入一条记录：

- 窗口**内**：既有行 `count + 1`、更新 `last_seen`，**不新增行、不写 outbox**；
- 窗口**外**：新增一行（`count = 1`）并写入一条 outbox 事件；
- 窗口以**首次出现时刻**（`received_at`）起算；
- 窗口时长与"当前时间"均通过注入时钟控制（可测试）；
- 并发安全：事务 + `pg_advisory_xact_lock(hashtext(fingerprint))` 串行化同指纹写入。

### 4. outbox

每条**新**告警写入 outbox 表一条 `alert.received` 事件，负载为规范化 JSON
（固定键序：source / severity / asset_id / fingerprint / summary / received_at）。
负载**只含告警字段**——签名值与密钥不进入负载（测试断言）。

### 5. 表与数据边界

| 项 | 决策 |
| --- | --- |
| 表名 | `test_alerts` / `test_outbox`（本轮仅测试；生产表名待运维确认） |
| 表名守卫 | 必须 `test_` 前缀的合法标识符，否则拒绝构造存储（防注入） |
| schema | 集成测试使用独立 schema `test_run_<时间戳>`，断言通过后删除；不触碰 public |
| 删除限制 | **不删除 public 模式中的任何表、不删除任何审计记录**（硬性约束 3） |

### 6. 本轮不做的事

- **不实现诊断**：不调用任何适配器、不执行任何命令、不读取任何 Secret；
- 不接入网关执行路径；不做告警转发/通知；
- 不实现告警源管理（source 白名单留待后续批次，见 TODO）。

### 7. 日志与错误

- 日志只记录 `fingerprint` 与服务端错误原因，**不记录签名值、密钥与请求体**；
- 响应错误信息不回显签名值/密钥；
- 服务端内部错误统一返回 500 且不暴露细节。

## 影响

- 新增 `alerts` 模块（`internal/ingest` 领域逻辑、`internal/httpapi` HTTP 层、
  `internal/store` PG 存储），已加入 `go.work`；
- 集成测试依赖 `internal/testdb` 的每轮独立 schema（H5）；
- 仓库级 AST 守卫（`internal/repoguard`）覆盖本模块：**出站** HTTP 调用
  （`http.NewRequest*`/`http.Client`/`http.Get`/`http.Post`/`http.DefaultClient`/
  client-go rest 等）在允许文件（两个适配器 client.go）之外一律禁止；
  **入站服务端用法**（`http.Server`/`http.Handler`/`http.NewServeMux`/
  `http.ResponseWriter` 等）放行——`alerts/internal/httpapi/server.go` 属此类。
  用途无法判定时 fail-closed 拒绝。该"出站/入站"细分与 H1 裁决的字面表述
  存在差异（见 TODO：待确认项）。
