# ADR-008：执行网关链路与共享内核模块化

- 状态：已接受（第十轮修订：模块化边界判定标准修正 + gRPC 接线完成）
- 日期：2026-10-12（第八轮；第十轮 2026-10-12 修订）
- 决策者：工程默认（待运维确认项已标注）

## 背景

第八轮实现执行网关（gateway）。网关需要复用 policy（策略引擎）、idempotency（幂等存储）、
audit（审计存储），但这三个包此前位于 `control-plane/internal/`；按 Go 的 internal 规则，
它们只能被 `github.com/ORG/agent-ops/control-plane/...` 路径下的代码导入，gateway 模块
（`github.com/ORG/agent-ops/gateway/...`）无法引用。第七轮遗留决策 D1/D2 同样要求
`internal/exec` 与 `internal/validation` 被 adapters、gateway、control-plane 三处共享，
单一模块的 internal 目录同样无法满足跨模块导入。

## 决策

### 1. 新增根共享模块

在 monorepo 根目录新增 Go 模块 `github.com/ORG/agent-ops`（go.mod 位于仓库根），
承载跨模块共享的 internal 包。由于该模块路径是所有子系统模块路径（
`github.com/ORG/agent-ops/<子模块>`）的公共前缀，Go 的 internal 规则允许各子系统
导入根模块的 `internal/*` 包。go.work 与 Makefile 的 GO_MODULES 同步加入该模块。

### 2. 包迁移（D1/D2 落地）

- `internal/exec`（新建）：共享 Runner 接口——argv 输入、RunOptions.Timeout 超时、
  输出上限 64KB（MaxOutputBytes）、stdout/stderr 截断标记与 TimedOut 标记。
  adapters/linux 只依赖该接口，不依赖传输实现。
- `internal/exec/ssh`（新建）：Runner 的 SSH 实现。**选型 golang.org/x/crypto/ssh，
  不调用 ssh 命令**。理由：①可在进程内启动测试 SSH 服务器，超时/截断行为无需外部
  sshd 即可确定性单测；②命令以 argv 传入，仅做与 OpenSSH 客户端相同的空格连接
  （session.Start），每个元素先经 validation.ValidShellToken 白名单把关
  （fail-closed），杜绝 shell 字符串拼接与重解释；③超时在进程内完成（关闭会话通道
  终止远端命令），不依赖 kill 外部进程；④无系统 ssh 客户端二进制依赖。
  安全默认：必须显式配置主机校验（HostKey/HostKeyCallback，不提供跳过选项）与认证。
- `internal/validation`（新建）：名称校验唯一来源（能力名 `^[a-z0-9_]+(\.[a-z0-9_]+)*$`、
  systemd unit 名 `^[a-zA-Z0-9@._-]+$`、绝对 Unix 路径、无 shell 语义 token）。
  删除 adapters/linux 与 control-plane/internal/registry 中的重复正则——
  linux 直接引用本包；registry 保留同名 API 但委托本包（行为一致由一致性测试保障）。
  ADR-007 中"名称校验实现于 internal/registry"的表述不变更其决策语义，实现位置
  以本 ADR 为准。
- `internal/policy`、`internal/idempotency`、`internal/audit`：由
  control-plane/internal 平移至根模块（含全部测试），仅调整导入路径；
  policy 的名称校验改为直接引用 internal/validation。
- gateway/internal/ssh 占位包删除（职责由 internal/exec/ssh 承接）。

### 3. 网关执行链路（固定顺序，不可绕过）

请求校验 → 能力查找（未声明即拒）→ **destructive 网关级直接拒绝**（先于策略，
不进入审批，不触达执行层）→ policy.Evaluate（纯函数）→ 网关低风险白名单门控 →
**审计决策**（先于执行；写入失败即 fail-closed 阻止执行）→ 按 decision 分支：

- deny：返回拒绝（已审计）；
- require_approval：只创建 pending 审批记录并返回 pending，不执行
  （批准后的自动执行留第九轮）；
- auto：幂等检查（同一 (actor, API="gateway.Execute", key) 只执行一次；
  同键不同内容 422；处理中/已放弃 409；同键同内容返回已存响应）→ 执行注册表
  Handler（带能力声明超时）→ **审计 executed/failed**（失败即请求失败，
  fail-closed；payload 不含错误原文与任何凭据）→ 写幂等响应。

决策审计事件 gateway.decision 覆盖 allow / require_approval / deny 三种结局，
执行结果以 gateway.executed / gateway.execution.failed 记录；审批创建以
approval.created 记录。所有 payload 只含元信息，不含 CredentialRef、参数与错误原文；
返回给调用方的错误信息经凭据形态字段掩码（工程默认启发式）。

**生产低风险自动执行清单为空**：auto 决策且等级非只读的能力，只有出现在
AutoExecAllowlist 中才执行，否则转审批。生产清单恒为空；测试清单必须注明「仅测试」。

### 4. 审批记录（B 项范围）

新建 gateway/internal/approvals：PostgreSQL 存储（本地 55432 部署实例），
状态 pending / approved / rejected / expired，仅存储与状态迁移
（pending → approved/rejected/expired，终态不可再迁），无任何执行逻辑。
试点表名 test_approvals（测试守卫要求 test_ 前缀），生产表名待第九轮确定。

### 5. 契约与 gRPC

本轮不改动 contract proto：执行请求以现有 protobuf 消息（Action/Environment/
AssetTarget 等）经 Go API 组装；gRPC 服务接线与 Execute RPC 消息在后续批次
（服务端监听接入时）一并定义。

## 修订记录

### 第十轮修订（2026-10-12）：共享内核模块化边界的判定标准修正

裁决：ADR-008 把 policy 与 idempotency 留在根共享模块这一决定**维持不变**，
但"只有单一调用方就回退"的判定标准存在缺陷，现修正如下。

**之前的判定标准（有缺陷）**：模块一旦只剩单一调用方就应回退到调用方内部。

**问题**：policy 与 idempotency 经 ADR-008 迁移到根共享模块后，目前唯一的调用方
就是 gateway；但 gateway（执行网关）恰恰是它们在设计上**应当所属的边界**——
策略与幂等都是执行链路的门控设施，从代码位置看放在网关侧并不比根共享模块
更"内聚"。按旧标准回退会破坏已通过的第八轮决策，且把两个有跨模块演进需求的
设施（控制层、节点 Agent 后续都要接入）提前钉死在单一子系统内。

**修正后的判定标准（即时生效）**：

> 模块是否回退到调用方，不看调用方数量，而看**单一调用方是否为该模块设计上
> 应属的边界**。若调用方就是它的设计边界（执行网关之于策略/幂等、审计之于
> 只追加存储），保留在共享位置；只有当单一调用方只是临时持有者（如为规避循环
> 依赖而做的中转、或尚未归属明确的过渡封装）时才回退。

**适用范围**：本次仅修正判定标准本身，不改变 ADR-008 已落地的代码位置
（`internal/policy`、`internal/idempotency` 仍位于根模块）。后续任何模块
的"是否内联/回退"评审均引用本条标准，避免再次出现以调用方数量为唯一依据
的判定。

### 第十轮修订（2026-10-12）：契约与 gRPC 的接线（原 §5 的后续批次）

原 §5 约定"gRPC 服务接线与 Execute RPC 消息在后续批次（服务端监听接入时）
一并定义"。第十轮完成该接线：

- `proto/agent_ops/contract/v1/gateway.proto` 在 Gateway 服务上新增
  SubmitExecute / Approve / Reject / ExecuteApproved / GetApproval 五个 RPC
  及配套消息（ApprovalRecord / ExecuteOutcome）；生成产物随仓库提交，
  `make gen-check` 校验一致性；
- 服务实现位于 gateway/internal/grpcwire，只做三件事：认证取 actor →
  契约消息与内部 Request 互转 → 固定错误码映射，不复制任何判定逻辑；
- 身份（actor）一律取自 gRPC metadata 中认证后的身份，契约消息中没有 actor
  字段；本轮认证为**仅测试的静态 token**（不得用于生产）；
- 固定错误码映射：策略拒绝 → PERMISSION_DENIED；幂等冲突 → ALREADY_EXISTS；
  审批状态不允许 → FAILED_PRECONDITION；审计失败 → INTERNAL；
- 注册表守护下沉为启动守卫（cmd/gateway 启动即调用 `AssertNoTestOnly`）。

## 影响

- control-plane 模块不再包含 policy/idempotency/audit（平移至根模块，测试随迁）；
- gateway 模块新增 internal/gateway（服务）、internal/linuxwire（Linux 能力接线）、
  internal/approvals（审批存储）；
- 集成测试：Docker 可用时真跑本地 sshd 测试容器（linuxserver/openssh-server，
  临时 ed25519 密钥对、127.0.0.1 随机端口、容器名前缀 agent-ops-sshdtest-），
  不可用则 skip 并输出原因，skip 不计入通过。
